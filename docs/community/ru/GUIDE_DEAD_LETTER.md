# Оповещение об окончательных сбоях доставки

## Перед началом

Подготовьте HTTPS-приёмник для событий notification.failed. Предоставьте операторам доступ к журналу приёмника и обеспечьте независимость этого пути от канала, который вы проверяете. [Способы установки](INSTALLATION.md).

## Подключение и настройка

1. Задайте адрес ниже в окружении воркера.
2. Настройте сохранение полей `notification_id`, `alert_group_id`, channel, `retry_count` и `last_error` на приёмнике и оповещение оператора.

```dotenv
NXS_ANOMALY_DEAD_LETTER_WEBHOOK_URL=https://hooks.example.org/dead-letter
```

Передайте параметры через окружение сервиса. В Helm используйте extraConfig для открытых значений и Secret приложения для ключей. После изменения окружения пересоздайте соответствующие процессы API и воркера.

## Проверка и устранение неполадок

В тестовой цепочке используйте управляемый приёмник, возвращающий HTTP 503. Дождитесь исчерпания попыток и сопоставьте ID доставки с событием. Восстановите тестовый приёмник. Для самого dead-letter POST отслеживайте `dead_letter_delivery_failed` в журнале воркера.
