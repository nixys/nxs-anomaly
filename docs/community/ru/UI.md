# Веб-панель и мобильный клиент

Веб-панель обращается к управляющему API `/api/v1` через обратный прокси
фронтенда. Перед публикацией настройте upstream API и аутентификацию;
контейнер фронтенда не заменяет серверную авторизацию.

## Обзор

Главная страница опрашивает `/api/v1/overview` каждые 15 секунд. Количество
открытых и подтверждённых инцидентов, ошибки и повторы доставки, интеграции
и дежурные загружаются одним ответом. При ошибке обновления последний успешный
ответ остаётся видимым, появляется повторная попытка. До её успеха данные
могут быть устаревшими. Это единый HTTP-ответ, а не транзакция всех разделов БД.

## Справочники и формы

Пользователи, команды, расписания, интеграции, цепочки эскалации и окна
обслуживания загружаются по 50 строк. Поиск выполняется на сервере по всей
коллекции, а не только по видимой странице. Для пользователей доступны имя,
username и email; для других справочников — имя. Приблизительное количество
помечается `≈`; переходите дальше, пока доступна следующая страница.

Списки выбора ищут удалённо с задержкой 250 мс после ввода и показывают первые
50 совпадений. Уточните запрос, чтобы найти значение за их пределами. Выбранные
значения запрашиваются по ID независимо от поиска: смена запроса не удаляет
существующий выбор. Ошибки загрузки показываются рядом с полем.

На небольшом экране таблица прокручивается внутри своего контейнера.
Элементы заголовков и карточек настройки переносятся, сохраняя читаемость
подписей. Фокус клавиатуры видим; приложение поддерживает обе темы.

## Первый инцидент дежурного

Откройте список групп, выберите открытую группу и проверьте интеграцию, исходные метки и время события. В таймлайне проследите выбранную цепочку до шага оповещения. Для подтверждения доставки найдите попытку нужного получателя в истории.

- Возьмите инцидент в работу действием **Acknowledge**. Группа перейдёт в подтверждённые, эскалация остановится.
- Для известного шума выберите **Silence** и срок. Проверьте время окончания подавления.
- Когда проблема устранена, нажмите **Resolve**. Проверьте закрытый статус и запись в таймлайне.



## Сессии

Кэш запросов веба и телефона очищается при выходе, отзыве учётных данных (401)
и входе в новую сессию. Временный отказ сервера (503) сохраняет кэш.
Если API недоступен при проверке пользователя, повторите подключение через
показанное состояние восстановления.

## Поведение мобильного клиента

Подключите телефон к серверу через pairing. Токены хранятся в системном
keychain. Запоздавший 401 старого клиента не отзывает новую сессию.
Не передавайте коды подключения и токены в сообщениях об ошибках.

Экран «Мои» помечает группы просмотренными, только когда вкладка в фокусе,
а приложение активно. На неактивной вкладке polling приостанавливается.
Доставка фоновых уведомлений также зависит от разрешений Android,
ограничений батареи и настроенного транспорта.

Ошибка обновления списка или следующей страницы сохраняет уже показанные
строки и предлагает повтор. После ошибки следующей страницы прокрутка
не вызывает бесконечные автоматические попытки. При первом открытии группы
показывается индикатор загрузки. Если последующее обновление не удалось,
сохранённая карточка остаётся видимой, но действия недоступны до восстановления:
клиент не смог проверить актуальный статус.

Запросы чтения поддерживают отмену. Мобильный HTTP-клиент использует нативный
XHR, сохраняет его timeout и снимает обработчики отмены после завершения.

## Границы проверки

Локальная Docker-приёмка проверяет реальные PostgreSQL/API/фронтенд-сценарии,
роли, маршрутизацию, действия с инцидентами, справочники и ширины браузера.
Jest проверяет переходы мобильного состояния и отмену XHR. TalkBack,
крупный системный шрифт, уведомления и переходы фон/активный режим перед
релизом требуют приёмки на Android-устройстве или ускоренном эмуляторе.

См. [API](API.md), [конфигурацию](CONFIGURATION.md) и [тестирование](TESTING.md).
