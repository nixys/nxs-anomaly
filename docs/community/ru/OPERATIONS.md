# Эксплуатация дежурной установки

## Приём смены

Откройте расписание в часовом поясе команды. Проверьте подмены и следующую передачу дежурства. Вместе с предыдущим дежурным просмотрите открытые и подтверждённые группы. Для каждого незакрытого инцидента зафиксируйте ответственного и следующее действие. После изменения расписания или канала отправьте тест на это расписание и проверьте получение на устройстве дежурного.

Проверьте процессы по отдельности. Задайте в API базовый URL сервиса, а в WORKER — доступный из вашей сети адрес HTTP-порта воркера. Для доступа к внутренним портам Kubernetes можно использовать port-forward. У API проверьте поле db_ok и версию, у воркера — успешный HTTP-ответ.

```bash
curl --fail-with-body "$API/health"
curl --fail-with-body "$WORKER/ready"
```

## Как найти причину недоставки

| Что видно оператору | Что проверить дальше |
|---|---|
| Источник получил ошибку HTTP | Сверьте путь обработчика и ключ. При 400 проверьте JSON после подстановки переменных. При 503 проверьте готовность БД и учитывайте Retry-After. |
| Источник получил успешный ответ, новой группы нет | Прочитайте результат приёма. Повтор мог попасть в открытую группу. Проверьте правила отбрасывания событий, окно обслуживания и предпросмотр маршрута. |
| Группа есть, попытки доставки нет | Откройте историю группы, проверьте выбранную цепочку, шаги ожидания и наличие дежурного. Проверьте /ready воркера и время последнего завершённого цикла. |
| Попытка пропущена | Прочитайте причину. Сверьте каналы получателя, учётные данные провайдера и политику исходящих соединений воркера. |
| Провайдер принял сообщение, дежурный его не видел | Сравните адрес назначения с контактом дежурного, проверьте очередь почтового релея или историю чата. Уточните у получателя, пришло ли уведомление. |

Перед изменением настроек запишите ID группы, интеграцию, время, канал и ответ провайдера. После изменения проверьте одну тестовую группу. [Проверка цепочки и доставки](CONFIGURATION.md) · [Метрики сервиса](ALERTING_RULES.md).

## Регламентные работы

- При ротации ключа приёма сразу обновите его у источника и проверьте срабатывание и восстановление. При смене ключа провайдера перечитайте окружение API и воркера и повторите тест доставки.
- Перед обновлением сохраните параметры релиза и сделайте резервную копию БД. Восстановите её в изолированную БД и проверьте готовность до подключения провайдеров доставки. [Резервное копирование](BACKUP_RESTORE.md) · [Миграции](MIGRATIONS.md).
- После обновления проверьте версию в /health, готовность воркера, покрытие расписания и получение тестового сообщения. Сравните ошибки приёма, ошибки доставки и глубину очереди повторов с обычными значениями под вашей нагрузкой. [Развёртывание](DEPLOY.md).
