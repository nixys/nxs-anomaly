# Первые шаги дежурного инженера

## Какую задачу решает nxs-anomaly

Система мониторинга обнаруживает проблему. Например, Prometheus вычисляет правило задержки, а Alertmanager отправляет webhook. nxs-anomaly принимает алерт, определяет ответственную команду и уведомляет дежурного. Дежурный подтверждает группу, расследует причину по данным мониторинга и закрывает группу после восстановления.

## Как проходит один алерт

| Компонент | Что происходит | Как проверить |
|---|---|---|
| Интеграция | Выдаёт источнику URL с ключом, задаёт группировку и маршруты | Событие содержит ожидаемые метки сервиса и критичности |
| API и PostgreSQL | Принимают событие и сохраняют алерт и группу | Группа появилась в веб-интерфейсе |
| Расписание и цепочка эскалации | Определяют получателя и следующий шаг, если никто не подтвердит группу | Выбран нужный маршрут, в расписании есть дежурный на текущее время |
| Воркер и провайдер доставки | Выполняют наступившие шаги и отправляют сообщение | В попытке доставки есть ответ провайдера, адресат получил уведомление |

**Алерт** — событие от источника. **Группа** объединяет связанные алерты и хранит состояние реагирования. Повторное срабатывание может обновить открытую группу. **Подтвердить** означает взять инцидент в работу. **Закрыть** означает завершить обработку группы.

## Пройдите путь от установки до передачи дежурства

1. Выберите способ [установки](INSTALLATION.md), запустите сервис и войдите в веб-интерфейс. Проверьте на API адрес `/health` и убедитесь, что `db_ok` равен true.
2. Отправьте [первый тестовый алерт](SETUP.md) на тестовой установке. Чтобы получить настоящее сообщение, укажите получателю явный канал и подключите провайдера. Канал по умолчанию log записывает уведомление в журнал.
3. Создайте команду, включите в неё получателя и задайте расписание с часовым поясом команды. В предпросмотре найдите текущего и следующего дежурного. Создайте цепочку с шагом `NOTIFY_SCHEDULE` и назначьте её интеграции по умолчанию. [Настройка](CONFIGURATION.md).
4. Отправьте событие firing с постоянным ключом инцидента по [примеру webhook](GUIDE_WEBHOOK.md). Откройте группу и её историю. Проверьте, что сообщение пришло тому, кто сейчас дежурит по расписанию.
5. Подтвердите группу. Отправьте событие восстановления из примера с тем же ключом группировки. Убедитесь, что закрылась именно эта группа. Запишите ID группы, получателя и время доставки, чтобы следующий инженер мог повторить проверку.

## Подключите рабочий мониторинг

Выберите формат отправителя в [каталоге интеграций](INTEGRATIONS.md). Начните с одного сервиса и одной команды. Перед переключением рабочего источника проверьте маршруты на его реальных метках через предпросмотр. Для передачи смены и разбора сбоев используйте [руководство по эксплуатации](OPERATIONS.md).
