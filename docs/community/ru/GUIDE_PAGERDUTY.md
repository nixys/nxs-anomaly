# PagerDuty Events v2

## Подготовка установки

Нужны работающие API и воркер nxs-anomaly, права редактора, тестовый получатель и доступ к настройкам отправителя. Из сети отправителя проверьте публичный HTTPS-адрес и сертификат. [Установка nxs-anomaly](INSTALLATION.md).

## Подключение отправителя

1. В nxs-anomaly создайте цепочку с уведомлением тестового пользователя. В разделе «Интеграции» создайте тестовую интеграцию типа `pagerduty`, назначьте цепочку по умолчанию и скопируйте ключ.
2. У отправителя с поддержкой Events v2 и смены адреса укажите приведённый ниже URL приёма. Ключ nxs-anomaly входит в URL. Если отправитель не задал `dedup_key`, сохраните его из ответа на trigger.
3. В тестовой оболочке задайте API с базовым адресом установки и KEY с ключом интеграции. Выполните запрос ниже из сети отправителя.

```bash
curl --fail-with-body -i -X POST "$API/integrations/v1/pagerduty/$KEY" \
  -H 'Content-Type: application/json' \
  --data-binary '{"event_action":"trigger","dedup_key":"checkout-test","payload":{"summary":"Checkout latency","severity":"warning","source":"checkout"}}'
```

## Проверка жизненного цикла

Отправьте запросы с `event_action` acknowledge и resolve, сохранив `dedup_key` первого события. Проверьте обе операции в одной группе. Без ключа повторные операции вернут ошибку валидации. В истории группы проверьте выполнение выбранной цепочки и сопоставьте попытку доставки с уведомлением у адресата.

После подтверждения доставки закройте тестовый инцидент соответствующим событием восстановления.

```bash
curl --fail-with-body -X POST "$API/integrations/v1/pagerduty/$KEY" \
  -H 'Content-Type: application/json' \
  --data-binary '{"event_action":"resolve","dedup_key":"checkout-test"}'
```

## Эксплуатация и диагностика

При неверной группировке или отсутствии доставки сравните поля и метки события с предпросмотром маршрута. При 404 проверьте полный путь и действующий ключ. При 503 учитывайте Retry-After. После ротации ключа сразу обновите отправитель и повторите тест. [Маршруты и уведомления](CONFIGURATION.md) · [Преобразование полей](ALERT_PROCESSING.md) · [Ответы HTTP](API.md).
