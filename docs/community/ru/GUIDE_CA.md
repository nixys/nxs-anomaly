# Подключение частного центра сертификации

## Перед началом

Экспортируйте цепочку CA в PEM и поместите в ConfigMap или Secret в namespace релиза. Проверьте имена и срок действия сертификата на стороне провайдера. [Способы установки](INSTALLATION.md).

## Подключение и настройка

1. Укажите имя и ключ набора customCA по примеру и обновите релиз.
2. API и воркер добавят набор к системным CA.
3. При изменении набора перезапустите поды.

```yaml
customCA:
  configMapName: corp-trust-bundle
  key: trust-bundle.pem
```

Добавьте фрагмент в values релиза с действующими настройками БД, секретов и образов. В репозитории версии установленного чарта задайте RELEASE и NS и примените полный файл values.

```bash
helm upgrade "$RELEASE" deploy/helm/nxs-anomaly -n "$NS" -f values.yaml --wait
```

## Проверка и устранение неполадок

Проверьте доставку на тестовый HTTPS-приёмник с этим CA. При unknown authority проверьте ключ монтирования и промежуточные CA. При несовпадении имени исправьте hostname или сертификат. При ротации установите новый CA до смены серверного сертификата.
