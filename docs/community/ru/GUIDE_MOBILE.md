# Мобильный клиент и push-шлюз

## Перед началом

Установите мобильный клиент проекта на тестовый телефон и откройте доступ к API по HTTPS. Для push подготовьте шлюз, который принимает ID устройства, platform, `push_token`, title, severity и `group_id` и передаёт уведомление провайдеру. [Способы установки](INSTALLATION.md).

## Подключение и настройка

1. Войдите в веб-интерфейс, выпустите одноразовый код привязки и введите его на телефоне.
2. Для доставки через шлюз зарегистрируйте push-токен устройства.
3. Задайте URL шлюза и при необходимости bearer-токен в NXS_ANOMALY_MOBILE_PUSH_TOKEN.

```dotenv
NXS_ANOMALY_MOBILE_PUSH_URL=https://push.example.org/notifications
```

Передайте параметры через окружение сервиса. В Helm используйте extraConfig для открытых значений и Secret приложения для ключей. После изменения окружения пересоздайте соответствующие процессы API и воркера.

## Контрольная проверка

Для второй проверки задайте ключ администратора и ID пользователя привязанного устройства. Успешный ответ означает приём шлюзом. Отдельно проверьте доставку на телефон.

```bash
curl --fail-with-body -X POST -H "X-API-Key: $API_KEY" "$API/api/v1/users/$USER_ID/test-push"
```

## Проверка и устранение неполадок

Создайте группу с этим адресатом и проверьте её появление в открытом приложении через SSE. Отдельно от администратора отправьте POST /api/v1/users/{id}/test-push и подтвердите получение на телефоне. При skipped проверьте URL шлюза и токен устройства. Для потерянного телефона отзовите сессию.
