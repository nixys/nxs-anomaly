# Уведомления OpenCVE в Telegram

Используйте этот сценарий, чтобы команда платформы получала CVE по своим продуктам, а команда баз данных — по своим. OpenCVE определяет, какие уязвимости совпали с подписками. Адаптер разворачивает входящий пакет в отдельные алерты. nxs-anomaly выбирает цепочку и отправляет сообщение в Telegram.

`OpenCVE → POST /webhook адаптера → интеграция nxs-anomaly → цепочка → Telegram`

## Перед началом

Понадобятся OpenCVE с поддержкой webhook-уведомлений, доступ к настройкам интеграций nxs-anomaly, Docker для адаптера и Telegram-бот с правом писать в целевые чаты. У OpenCVE должен быть сетевой доступ к HTTPS-адресу адаптера, а у адаптера — к адресу приёма алертов nxs-anomaly.

Триггер **A CVE enters this project** срабатывает при первом совпадении с подписками проекта. CVE могла быть опубликована раньше, если затронутый продукт появился в её данных позже. Если важна свежесть публикации, настройте условие по дате в OpenCVE при наличии этой возможности. Адаптер отправляет выбранные OpenCVE события. Alert automations обрабатывают часовые окна, поэтому время публикации CVE и время уведомления могут различаться. [Автоматизации OpenCVE](https://docs.opencve.io/guides/automations/)

## 1. Выберите, как делить уведомления

| Требование | `OPENCVE_ROUTING` | Значение метки `subscription` |
| --- | --- | --- |
| Один проект на чат или команду | `project` (по умолчанию) | Имя проекта, например `platform` |
| Один проект, разные чаты по совпавшим продуктам | `subscription` | Каждый элемент `changes[].cve.subscriptions.raw`, например `vendor$PRODUCT$product` |

В режиме `subscription` одна CVE может попасть в несколько чатов. Адаптер формирует отдельный алерт на каждое совпадение, а nxs-anomaly выбирает первый подходящий маршрут для каждого из них. При необходимости добавьте в условие метки `organization` и `project`. [Формат вебхука OpenCVE](https://docs.opencve.io/concepts/notifications/#webhook)

## 2. Настройте цепочки в nxs-anomaly

1. Задайте `NXS_ANOMALY_TELEGRAM_BOT_TOKEN` в окружении процесса доставки. Добавьте бота в нужные чаты.
2. Создайте по получателю на чат и укажите явный адрес в профиле. Для доставки через Bot API достаточно цели `"notification_targets": [{"type":"telegram","target":"-1001234567890"}]`. Подставьте фактический chat ID.
3. Создайте по цепочке с шагом `NOTIFY_USER` для каждого получателя. Если для CVE нужно подтверждение дежурного, настройте цепочку с расписанием и эскалацией.
4. Создайте интеграцию типа `webhook`. Добавьте точные правила по `labels.subscription` для `platform` и `databases` и один маршрут по умолчанию. Назначьте маршруту по умолчанию цепочку, в которой можно заметить подписку с опечаткой или новый проект.
5. Скопируйте URL приёма интеграции для адаптера. Адрес имеет вид `https://anomaly.example.com/integrations/v1/webhook/<key>`.

Пример одного правила интеграции:

```json
{
  "name": "Platform CVEs",
  "match_type": "labels",
  "labels": {"subscription": "platform"},
  "escalation_chain_id": "chn_platform"
}
```

Пример текста в `templates.telegram`:

```text
{{ .title }} · {{ .label_subscription }}
{{ if .label_cvss }}CVSS 3.1 {{ .label_cvss }}
{{ end }}{{ .label_summary }}
{{ .label_cve_url }}
```

Подробности о [цепочках и маршрутах](CONFIGURATION.md) и [переменных шаблона](ALERT_PROCESSING.md).

## 3. Запустите адаптер и привяжите уведомление OpenCVE

Из корня репозитория соберите образ командой `docker build -t nxs-opencve-adapter deploy/opencve`. В приватном файле `adapter.env` задайте:

```dotenv
OPENCVE_WEBHOOK_TOKEN=<случайный токен для входящего вебхука>
NXS_ANOMALY_WEBHOOK_URL=https://anomaly.example.com/integrations/v1/webhook/<key>
OPENCVE_ROUTING=project
```

Если на интеграции включён `webhook_secret`, задайте адаптеру `NXS_ANOMALY_WEBHOOK_SECRET` с фактическим значением секрета. Адаптер подписывает тело вместе с отметкой времени. В production-профиле настройте саму интеграцию через ссылку `env:ИМЯ_ПЕРЕМЕННОЙ`. [Параметры подписи](API.md)

```sh
docker run -d --name opencve-adapter --restart unless-stopped \
  --env-file adapter.env -p 127.0.0.1:18081:8080 \
  -v opencve-adapter-data:/data nxs-opencve-adapter
```

Опубликуйте `/webhook` через HTTPS-прокси. В проекте OpenCVE создайте уведомление типа Webhook, укажите этот адрес и добавьте заголовок `X-OpenCVE-Token` со значением `OPENCVE_WEBHOOK_TOKEN`. Привяжите уведомление к действию **Send a notification** в alert automation проекта. Учётные данные UI и API OpenCVE для этого не нужны. [Настройка уведомления OpenCVE](https://docs.opencve.io/concepts/notifications/#webhook)

## 4. Проверьте маршрут и доставку

Используйте тестовую интеграцию и чат. Сначала проверьте готовность адаптера через `GET /health`, затем отправьте синтетический пакет. Установите переменную `OPENCVE_WEBHOOK_TOKEN` в текущей оболочке и подставьте имя своего тестового проекта.

```sh
curl --fail-with-body http://127.0.0.1:18081/webhook \
  -H "X-OpenCVE-Token: ${OPENCVE_WEBHOOK_TOKEN}" \
  -H 'Content-Type: application/json' \
  --data '{
    "organization": "demo",
    "project": "platform",
    "changes": [
      {"cve": {"cve_id": "CVE-2099-0001", "description": "Проверка доставки", "cvss31": 8.1,
               "subscriptions": {"raw": ["platform"]}}}
    ]
  }'
```

При первом проходе ожидайте `{"accepted":1,"duplicates":0}`. Повтор пакета на том же томе вернёт `{"accepted":0,"duplicates":1}`. Затем откройте группу в nxs-anomaly и проверьте `subscription`, цепочку и попытку доставки. Ответ адаптера подтверждает приём алерта в nxs-anomaly. Факт доставки подтверждается отдельной попыткой со статусом `delivered` и сообщением в целевом чате. [Проверка доставки](CONFIGURATION.md#как-читать-результат)

## Если уведомление не пришло

| Что видно | Что проверить |
| --- | --- |
| `401` от адаптера | Значение и имя заголовка `X-OpenCVE-Token` в OpenCVE. |
| `400` от адаптера | Есть ли `organization`, `project`, `changes[]` и корректный `cve_id`. В режиме `subscription` каждому CVE нужен массив `subscriptions.raw`. |
| `413` от адаптера | Тело запроса превышает лимит в 1 МиБ. |
| `502` от адаптера | Доступность nxs-anomaly, URL и ключ интеграции, секрет HMAC, синхронизацию часов. После устранения причины повторите исходный пакет. |
| Алерт ушёл в маршрут по умолчанию | Сверьте исходные метки алерта и порядок маршрутов. Метки, добавленные пайплайном, появляются после выбора маршрута. |
| Алерт есть, сообщения нет | Проверьте, что цепочка поставила уведомление в очередь, затем посмотрите причину в попытке доставки. Сверьте токен бота, chat ID и права в чате. |

## Повторная отправка и хранение

Запускайте один экземпляр с постоянным томом `/data` на интеграцию. Адаптер запоминает успешный приём по сочетанию организации, проекта, подписки и CVE. После частичного сбоя повтор пакета пропускает уже записанные элементы. Записи сохраняются до удаления тома, поэтому последующее изменение той же CVE по той же подписке также будет пропущено.

Обновите nxs-anomaly перед развёртыванием этой версии адаптера. Если ответ потеряется до записи в SQLite, адаптер повторит отправку с тем же ID события. Пока исходный алерт хранится, nxs-anomaly подтвердит повтор как дубликат, в том числе после закрытия группы. У алертов, принятых до обновления сервера, нет ID события. При обновлении сохраняйте том SQLite.

### Разбор пакета после ошибки

`/health` проверяет HTTP-процесс. Для проверки связи с nxs-anomaly нужен тестовый пакет. Пустой `subscriptions.raw` в режиме `subscription` даёт ноль алертов для этой CVE. Ответ `202 dropped_by_pipeline` от интеграции превращается в `502` адаптера. Проверьте правила drop перед повтором: при той же конфигурации обработка остановится на том же элементе.

Внутри пакета адаптер пересылает элементы последовательно с сетевым таймаутом 10 секунд на вызов. Одновременно могут пересылаться до восьми пакетов. При перегрузке адаптер отвечает `503`, пакет можно отправить повторно. `/health` отвечает во время пересылки. Учитывайте число совпадений при настройке таймаута прокси. SQLite хранит ключи принятых алертов и подтверждённых повторов. Повторите исходный POST с тем же токеном и постоянным томом. При вводе в эксплуатацию проверьте реальную доставку из OpenCVE в чат.
