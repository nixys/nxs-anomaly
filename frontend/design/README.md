# Design export

Готовит материалы для дизайнера, работающего над макетом в Figma: снимки всех
экранов продукта и токены темы, вытащенные из живого приложения.

Зачем это нужно именно так. Figma REST API не умеет создавать содержимое файла —
на запись доступны только комментарии, dev-resources и переменные (последние на
Enterprise-тарифе). Строить фреймы и слои может лишь Plugin API, то есть код
внутри Figma. Поэтому «CI сам собрал макет» невозможно; автоматизируется всё, что
до Figma, и импорт одним действием внутри неё.

## Запуск

Нужен доступный PostgreSQL — тот же, на котором работает e2e:

```sh
export NXS_ANOMALY_TEST_DATABASE_URL='postgres://user:pass@localhost:5432/nxs_anomaly_design?sslmode=disable'
npm run design:export     # скриншоты + токены
npm run design:capture    # только скриншоты
npm run design:tokens     # только токены
```

Playwright сам поднимает Go API и Vite (тот же `webServer`, что у e2e) и гасит их
после прогона. Результат — в `frontend/design-export/`, каталог в `.gitignore`.

**Берите отдельную базу.** Прогон засеивает демо-данные и оставляет их в БД;
на рабочей базе они смешаются с настоящими.

## Что получается

```
design-export/
├── screens/  *.png        68 кадров: 17 экранов × dark/light × desktop/mobile
├── screens.json           манифест: файл → экран, роут, тема, ширина
└── tokens.json            токены темы для Tokens Studio
```

### screens/

Full-page снимки при 1440×900 и 390×844. Мобильная ширина ниже брейкпоинта `sm`,
где навбар уходит под бургер, — это другая раскладка, а не суженная, и именно её
чаще всего забывают.

Детальные экраны (`alert-group-detail`, `integration-detail`, `schedule-detail`)
снимаются переходом по первой ссылке со списка. Если список пуст — кадра не
будет; `schedule-detail` пропускается, пока seed не создаёт дежурства.

### tokens.json

Все переменные `--mantine-*`, снятые через `getComputedStyle` на живой странице в
обеих темах, в нативном формате Tokens Studio (два набора: `mantine-dark`,
`mantine-light`). Это не документированные дефолты Mantine, а то, что реально
рендерит эта сборка, включая любые будущие переопределения в `createTheme`.

Дизайнеру: плагин **Tokens Studio for Figma** → Import → выбрать `tokens.json` →
Create Variables. Переменные Figma после этого совпадают с продом по построению.

## Что остаётся ручным

- **Редактируемые слои.** Импорт живых страниц плагином html.to.design (батч
  есть только в их платном API). Даёт слои вместо картинки, но не компоненты.
- **Сборка библиотеки** из Mantine UI Kit — 43 используемых компонента кита плюс
  18 собственных, которых в ките нет (`components/common.tsx`, `StatTile.tsx`).

## Демо-данные

`seed.ts` создаёт цепочку эскалации, трёх ответственных, интеграцию и семь
алертов с разной severity — так, чтобы один снимок списка показывал все цвета
бейджей сразу, включая нарочито «бедную» строку без labels: на ней раскладка
ломается раньше всего.

Экраны Teams, Schedules и Maintenance остаются в empty-state — их API seed не
трогает. Если дизайнеру нужны и они, добавьте вызовы в `seedDemoData()`.

## Если понадобится править

- `capture.spec.ts` — список роутов `ROUTES` намеренно записан вручную, а не
  выведен из `Shell.tsx`: забытый роут должен быть виден здесь.
- `shared.ts` — тема ставится через `localStorage` до загрузки страницы, а не
  кликом по переключателю в шапке (тот зависит от языка интерфейса). Ключ
  Mantine проверяется ассертом на `html[data-mantine-color-scheme]`: если ключ
  когда-нибудь сменится, прогон упадёт, а не выдаст два одинаковых тёмных набора.
